# gradle/

## Responsibility

`gradle/` owns root build support files that are consumed by Gradle itself and by AniTrend `buildSrc` convention logic. It centralizes dependency versions, plugin aliases, release version properties, wrapper distribution metadata, and daemon JVM toolchain metadata.

Key files:

- `gradle/libs.versions.toml` is the version catalog for plugin and library aliases.
- `gradle/version.properties` contains the app release version, numeric code, and release name used by build config generation.
- `gradle/wrapper/gradle-wrapper.properties` pins the Gradle distribution and wrapper download behavior.
- `gradle/gradle-daemon-jvm.properties` records the daemon toolchain version, vendor, and platform download URLs generated by Gradle.
- `gradle/wrapper/gradle-wrapper.jar` is the binary wrapper launcher and is not described further in text codemaps.

## Design Patterns

- Version catalog pattern: shared versions live in `[versions]`, plugin aliases in `[plugins]`, and dependency aliases in `[libraries]`.
- Catalog alias consumption: `buildSrc` and Gradle scripts use generated `libs.*` accessors rather than raw coordinates.
- Release property file pattern: `PropertiesReader` in `buildSrc` loads `version` and `code` from `gradle/version.properties`.
- Wrapper pinning pattern: wrapper properties provide reproducible Gradle distribution selection.

## Data & Control Flow

1. Gradle reads wrapper metadata before the build starts when invoked through `./gradlew`.
2. Gradle exposes `libs.*` accessors from `gradle/libs.versions.toml` to root build scripts and `buildSrc`.
3. `buildSrc` plugin components read catalog aliases for external dependencies, plugins, Kotlin versions, and Spotless or ktlint versions.
4. `ProjectProperties.kt`, `ProjectConfiguration.kt`, and `ProjectOptions.kt` read `gradle/version.properties` to populate app default config and library build config fields.
5. Gradle daemon JVM metadata supports consistent Java toolchain selection outside app runtime code.

## Integration Points

- `buildSrc/build.gradle.kts` uses catalog aliases for plugin implementation dependencies.
- `buildSrc/src/main/java/co/anitrend/buildSrc/plugins/components/ProjectDependencies.kt` consumes most library aliases for automatic module dependency wiring.
- `buildSrc/src/main/java/co/anitrend/buildSrc/plugins/components/ProjectConfiguration.kt` uses catalog versions and `version.properties` values during Android configuration.
- Renovate or dependency update automation can modify catalog values without touching module build logic.
